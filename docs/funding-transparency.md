# Funding and transparency layer

## Current state

All public pages are in **Research funding model** or **Investment interest** state. Albedo does not offer investments, accept investor funds, publish a live target or process payments through this website. Candidate interest forms are non-binding research inputs only.

The central methodology is `/#/infrastructure/funding`. Every configured candidate has a linked `/#/infrastructure/{country}/{candidate}/funding` page generated by `InfrastructureFunding.tsx`. Each candidate is financially separate by default; no portfolio pooling or reallocation is implied.

## Reporting architecture

`src/data/fundingTransparency.ts` defines typed placeholders for funding gates, use-of-funds categories, a conventional public ledger and a funding snapshot. All monetary values are `null`. Do not place live commitments, receipts, expenditure or distribution data in frontend configuration. Future live values must come from an authenticated, operator-controlled server source with an audit trail.

The public interface keeps four concepts separate:

1. non-binding interest;
2. legally verified commitments;
3. funds legally received;
4. funds documented as deployed.

Before funding opens, all four display as not applicable rather than numerical zero. The use-of-funds and ledger components publish explicit empty states. Returns, ownership and distribution reporting is architected only as explanatory copy; no return, yield, unit price or ownership figure is displayed.

## Future provider configuration

The provider pathway is disabled by default:

```env
VITE_CROWDFUNDING_PROVIDER_ENABLED=false
VITE_CROWDFUNDING_PROVIDER_NAME=
VITE_CROWDFUNDING_PROVIDER_PROJECT_URL=
VITE_CROWDFUNDING_PROVIDER_CANDIDATE_ID=
```

The external offer link renders only when the flag is exactly `true`, the provider name is present, the URL is HTTPS, and an explicit candidate ID is supplied. On candidate pages that ID must match the page. This configuration is a display adapter only; Albedo never receives payment through it.

Do not enable it until all of the following are verified and approved:

1. A project-specific legal vehicle, owner, directors and jurisdiction exist.
2. Technical feasibility, commercial validation, site and grid dependencies are disclosed.
3. A complete financial model, minimum and maximum targets, deadline and failure consequences are approved.
4. Use of funds, fees, conflicts, investor rights, cancellation, complaints, risk factors and refund treatment are complete.
5. An appropriately authorized European crowdfunding provider has accepted the exact project offer.
6. Provider authorization, exact offer URL and offering documents have been independently verified.
7. Privacy, investor-classification, marketing, financial-promotion and recordkeeping reviews are complete.
8. An authenticated reporting source and approval workflow exist for commitments, receipts, expenditure, corrections and distributions.
9. A production review confirms that no payment details or identity documents are collected by Albedo’s public form.
10. The deployment is approved explicitly; configuration alone is not legal approval.

For a development-only rendering check, use a non-production build and harmless HTTPS documentation URL. Never deploy the placeholder:

```bash
VITE_CROWDFUNDING_PROVIDER_ENABLED=true \
VITE_CROWDFUNDING_PROVIDER_NAME="Development provider" \
VITE_CROWDFUNDING_PROVIDER_PROJECT_URL="https://example.com/not-an-offer" \
VITE_CROWDFUNDING_PROVIDER_CANDIDATE_ID="EU-ES-01" \
npm run build
```

## Candidate interest storage

Migration `202608030003_funding_interest_fields.sql` adds optional residence/establishment country, basic investor self-identification, preferred instrument, preferred stage and notification preference to the protected investor/partner table. The Edge Function allowlists enum values. This is not suitability testing or a legal investor classification.

## Rollback

Set `VITE_CROWDFUNDING_PROVIDER_ENABLED=false` or remove all provider variables and redeploy. The external link disappears and the non-binding interest path remains. If reporting data is later server-backed, disable its authenticated feed independently; never replace missing verified records with frontend estimates.
